# Astra 整体设计评审与修改理由

日期：2026-09-27。评审模型：`gpt-6-astra`。范围：最终 Data 设计、Notebook 与假设 demo；忽略现有 `axiom-data` 实现。

后续范围确认（2026-10-03）：用户已启用完整财务、股东、生命周期/PIT 证据、供应商 dated 历史成员快照及延续政策与双教程。本页保留当时简化管理对象的评审理由；“按需扩展”不再意味着这些已启用域可延后交付。当前合同以 `02_axiom_data.md` 与完整验收清单为准。

## 结论

原设计的科学内核值得保留，完整工程形态对个人日频系统存在明显过度设计。个人维护者需要可靠更新、几行 Python 查询、解释缺数、固定旧实验输入和恢复，而不应先维护多种独立产物的发布、索引、准入和撤销流程。

已将首版收敛为三类持久数据：

```text
原响应 + fetch日志
       ↓
带版本的规范Parquet分区
       ↓
Snapshot JSON：按域列完整分区、合同、来源与构建版本
       ↓
Reader(snapshot, QuerySpec) → DataBatch(frame, field_meta, context)
```

## 修改与理由

| 原要求 | 当前个人版 | 为什么 |
|---|---|---|
| 每次请求独立RawBatch目录/清单 | 原响应文件去重，fetch日志记录每次请求 | 保留观察历史，同时减少小文件和管理对象 |
| 独立DomainCommit发布与引用 | Snapshot内的domains段保存域状态 | 独立域版本的含义保留，首版不再维护第二层发布系统 |
| DerivedCommit独立生命周期 | 确定函数；确有成本时加身份绑定缓存 | 先解决实际计算需求；真正被独立发布的结果再升级为产物 |
| 每次View需要manifest/ID/发布 | QuerySpec + Reader返回上下文；实验保存实际查询 | 读取不必变成资产登记动作；代码、数据和时间口径仍能固定 |
| Qlib及多后端一致性是首版前提 | 实际采用Qlib时再增加导出与校验 | 避免长期维护尚无消费者的第二套格式 |
| 通用CodeBundle、dirty/untracked捕获与执行平台 | 可恢复commit、实际配置、依赖锁；重要发布再归档 | 保留重现能力，缩小构建基础设施；不能只记hash却丢文件/代码 |
| 通用证据、认证、准入与撤销系统 | 按当前用途的范围检查、issues及少量证据引用 | 行情任务不应被无关财务/股东缺口阻断；已知错误仍须处理 |
| PIT被理解为逐级升级 | 分开“市场公开可知”和“本系统实际拥有”两个问题 | verified不能改写真实first_observed，也不能代替operational |
| 全部数据域、消费者、边界用例同时建设 | 先一条市场研究闭环，再按需求接财务/股东/消费者 | 让真实使用决定扩展，避免治理完成而研究仍跑不通 |

没有删掉：原响应、规范单位/键、必要revision、per-session cutoff、动态历史成员、停牌/缺数/退市区别、旧输入可恢复、Feature与数据的独立版本轴。

## 是否科学，以及更好的取舍

科学性由因果时间、样本选择、价格/收益口径和可重复对照保证，不由artifact数量或绿色状态数量保证。

- 2026年首次获得的2020终态财务，不能靠hash或Snapshot补成历史vintage；明确best-effort比制造strict资格更诚实。
- historical membership、退出证券、公司行动、复权和缺数排除是高价值正确性工作。排除异常股票可能改变样本分布，要保留原因及数量。
- 第一版只做实际需要的域和字段。尚未出现昂贵重复计算时不建派生发布系统；没有第二后端时不做后端通用等价平台。
- 一个Snapshot加一份完整QuerySpec、Reader代码版本与实验配方，就能保留关键对照能力。可以合并管理对象，不能混淆事实版本、可知时间和研究配方。

## 从零实施估计（按后续讨论修正）

原Astra评审按人工每周25—30小时推进项目，混合了联调与运行观察。后续讨论明确采用AI持续实现、人工及时确认来源语义，当前计划调整如下；这是实施粗估，不是已完成工作的证明。

| 累计交付 | 当前估计 |
|---|---:|
| 三层存储、Snapshot、Reader、假设数据闭环 | 1—3天 |
| 一个来源与真实小窗口、增量/续跑、关键验证 | 3—7天 |
| 首版沪深300历史行情研究可用、范围检查与恢复 | 约1—2周 |
| 财务、股东、Qlib等扩展 | 实际需要时接入，另行估时 |

假设主要来源和权限可用，范围不含完整Engine/UI或实盘。限流、下载量、源历史能力和授权等待可能影响时间；运行观察可与研究并行。当前不再使用原6—9周作为首版实现的等待时间。

开始实现只需补实际供应商合同、少量公共接口、固定Raw与独立预期、可执行的端到端完成命令。内部函数由AI组织；harness先采用普通测试和Notebook，一页AGENTS.md提供边界/入口/命令，无需专用Agent平台。

## 难点与注意事项

1. 历史成分及退出证券覆盖，防止幸存者偏差。
2. 公司行动、复权、成交和账户收益口径一致，防止分红双算与退市估值失真。
3. 财报累计/单季、修订、撤销及实际可知时间，防止终态值倒灌。
4. 分页、源延迟、重复/失败续跑及修订窗口，防止采集器自己制造缺口。
5. 保持一个真实研究闭环先行，避免先建设通用平台。

Axiom的单位、映射、日期、去重等错误属于必须修复的缺陷，不能算供应商容错。无法承诺零错误；统一转换、少量高价值真实样本、必要反例和可重建性，比重复全历史检查更有效。

## 本轮同步与验证

主设计为 `docs/design/02_axiom_data.md`，总纲、Core、Trade、Research、UI及两个补丁同步个人版Data要求。Notebook与demo改为相同三层结构，删除对独立DomainCommit/View产物的首版依赖。

保留前轮已修好的具体语义：B停牌与A成交一致、FeatureRelease不绑Snapshot、接口实际读取Parquet、共享字段元信息、早盘不可见日线、明确修订顺序、历史补采与日更区分。

Notebook逐格运行并检查实际展示的不变量：旧Snapshot不变、未变域文件复用、Raw内容引用、PIT边界、返回schema和状态一致。没有为设计文档增加产品测试框架。

## 最后一致性检查

本轮同步了主设计、Notebook、HTML和本说明的AI实施时间口径；把公共写操作与读取返回值区分清楚；Snapshot分区字段统一为`partition`；明确单次复权价格窗口使用同一个锚点；补上最小实现交接及普通harness要求。补丁A也明确Financial RC是后续财务纵向案例，不阻止行情版先交付。

结论：文档足够作为精简首版的实现输入，仍需接源时确认真实字段和历史能力。本轮验证设计与假设demo的一致性，不代表真实数据已经采集或产品实现已经通过验收。


2026-10-03 用户进一步确定生产数据只用 Tushare；外部核对只作 warning，撤销必须闭合官方调样链或核对每个退市公告的生产门槛。成员默认延续截至研究日最近一份可见供应商快照，不用月底快照回填月初；PIT 表达信息边界，不保证收益偏差只向下。此决定覆盖此前评审中的来源建议。


本轮Qlib已由用户启用并完成，早期“实际采用再接入”是阶段原则，当前交付范围以Data设计为准。
