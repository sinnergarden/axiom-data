# 批处理、财务事件与重复数据

性能验收分别观察请求数量、网络等待、规范化与写入、重复更新、读取和重建。测试通过不等于吞吐量达标，一年行情的耗时也不能代表包括财务事件的完整初始化。

## 采集和处理的批次

行情默认按交易日取全市场，随后按冻结的标的集合筛选 Canonical。财务优先使用供应商支持的批量窗口，响应触顶时才缩小范围。来源的确切选择器与截断行为必须先核对，不能只为减少请求而遗漏数据。

请求共享限速器并使用有界并发；不是每个 worker 各享 300 次/分钟。已成功落地的 Raw 在恢复时复用。网络错误需要重试请求，规范化错误应修复后重放已存 Raw，不应重新拉取整个任务。

初始化需要财务 warmup。日更必须有界地回看可能新披露或修订的数据，不能每次重拉初始化范围。供应商若会修改旧报告却不改变可检索的公告日期，短窗口日更无法保证发现这些更改；这类情况使用明确的历史 refresh。具体窗口随冻结计划保存。

## 财务事实怎样存

同一来源域用有类型的 Parquet 宽表保存所需字段，采用 Zstandard 压缩。报表的经济键包含稳定证券身份、报表来源、报表类型和报告期；金额单位与累计值/期末值口径在合同中声明。

报告期、公告日期、实际公告日期、首次观察时间和 revision 分开。报告期作为经济键的一部分，财务按报告年度分区；修订仍留在同一报告年度。股东报告按整组替换，避免旧版股东残留。事件不复制到每个交易日，单季、TTM 和按日可用值在查询或派生时计算。

PIT 先过滤该 cutoff 可见的版本，再按声明的修订规则选择。供应商公告日假设和系统实际首次观察时间不能互相代替；不能用一个今天收到的最新值无条件回填过去。

## 哪些重复应当消除

| 情形 | 持久化行为 |
| --- | --- |
| 再次收到完全相同的响应字节 | 复用同一 Raw 内容对象，只新增本次请求和接收时间日志 |
| 响应顺序或格式变了，但规范事实连续相同 | 原响应仍可追溯；Canonical 保留已有事实和首次观察时间 |
| 连续观察 `A → A → A` | 不新增 Canonical 修订，不重写分区，不因接收日志单独发布 Snapshot |
| 真实观察 `A → B → A` | 保留三次状态，后一个 A 不能与第一个 A 合并，否则会改写中间历史 |
| 仅一个报告年度发生变化 | 写该年度的新分区对象，其他年度和域继续引用原文件 |
| 新 Snapshot | 保存文件引用和解释配置，不复制全库 |
| 重复研究查询 | 允许有界缓存；不要求先物化一份每日财务 View |

不可变分区会在真正修订时产生新文件，旧 Snapshot 引用的版本仍需保留。因而这里的去重不是承诺“每个标量在所有历史版本中只占一份字节”。先测实际写放大，再决定是否需要更细分区；不为少量财务记录预建每证券/每字段小文件或多层增量存储系统。

供应商成员按变更区间保存，完整 dated 组作为压缩状态固定在Snapshot。相同成员延续时不逐日写1800行；真实新快照或覆盖变化才生成新的manifest，相同Parquet仍可复用。Raw同值观察另留日志。来源配置沿Snapshot父链保存增量，不每次复制整个历史身份与请求集合。快照延续是已接受的研究政策，不是官网历史调样认证。

## 读取与校验的范围

按报告期查询时，只读相关 `period-YYYY` 分区，并投影所需列和证券。按可更正的公告日或生效日查询时，不能简单按旧日期裁剪；必须先正确选择版本。当前测试用十二个报告年度验证：单年度报告期查询读一个分区，同一公告日覆盖十二个报告年度时读十二个分区。

普通查询不执行全库审计。文件完整性校验在同一 Store 实例内按文件状态缓存；完整 Raw 对照审计、离线重建和迁移校验是明确操作。增量更新只处理受影响分区，离线重建按有限内存批次处理 Raw。

成员 Reader 每次查询建立一次证券区间索引、完整集合状态和覆盖检查点；每个 session 的 PIT 可见性只计算一次。完整集合以区间引用表达，不在每个状态复制全部名单；相同来源依赖列表在结果元数据中共享，避免按“证券 × 日期”重复生成数百个 Raw ID。

真实成员读取测量（本地记录：`docs/membership-read-measurement.json`）使用供应商月末快照及延续政策，读取1996个历史候选×2026年6月21个开市日，共41916个结果；各日1800个成员。首次约1.59秒，缓存重读约0.34秒，读取一个Parquet分区，默认64MiB结果缓存命中。元信息显示6月初使用5/29快照、6/30使用6/30快照。它没有控制OS页缓存，不代表冷盘或十二年大查询耗时，也没有保存View文件。

本地合成测量见 Raw 去重记录（本地记录：`docs/raw-dedup-measurement.json`）：100 次完全相同的 1 MiB 响应，仅保存一个 1 MiB 内容对象与 38,700 字节观察日志。该测量验证存储行为，不能替代真实完整采集的耗时和容量报告。
